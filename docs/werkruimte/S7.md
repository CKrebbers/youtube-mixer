## 2. Vakken

Een vak is een naam in de werkruimte. Op een tweede scherm of de iPad een lijst
(`delen.<deel>.schermen.<scherm>.vakken`), in de mixer één (`delen.<deel>.schermen.hoofd.werkvak`):

| vak | wat | mac-2 | iPad | werkvak (mixer) |
|---|---|---|---|---|
| `uitlijn`, `uitlijn-pagina`, `uitlijn-strook`, `uitlijn-vouw`, `uitlijn:<vorm>:<1\|2>` | de uitlijnweergave van S2 (`src/uitlijn/teken.js`) | ja (slepen = duwen) | ja (uit segmenten; alleen kijken) | ja (S2's `toonVak`) |
| `paneel:<id>` | een vrij paneel uit `panelen.<id>` | ja (bedienen) | ja (kijken) | ja (de gewone controls van de mixer) |
| `kaart` | wat elke knop in het open mapje nu doet | ja | ja | ja |
| `stand` | per track nummer, titel, bpm, tijd (wat je hoort); de maatgever | ja | ja | — |
| `fx`, `fx:<n>` | BOUWSTEEN: het rack van de focus-track (of track n): 8 plekken met de naam die het rack erop zet, mix, aan/uit, rack ◀ ▶, 8 worpen, de superknoppen van S4 | ja | ja | ja |
| `strip`, `strip:<n>` | BOUWSTEEN: trim, EQ, filter, echo, galm, fader, kills, op de maat, sync, PFL | ja | ja | ja |
| `mixer` | BOUWSTEEN: filter en fader van alle acht, crossfader, master | ja | ja | ja |
| `stems`, `stems:<n>` | BOUWSTEEN: per stem weg, filter, echo | ja | ja | ja |
| `master` | BOUWSTEEN: het master-rack (8 plekken, mix, aan/uit, rack ◀ ▶) en het volume | ja | ja | ja |
| `sampler` | BOUWSTEEN: de acht pads, korter/langer, volume | ja | ja | ja |
| `library` | zoeken en de lijst (lezen); als venster van de mixer laadknoppen 1–8 (tweede druk over een spelende track) | ja | ja (zonder laden) | — |
| `secties` | de secties van de focus-track, de sectie die je hoort wit | ja | ja | — |

Een onbekende naam: een melding en verder niets (geen raden). Een BOUWSTEEN is een paneel dat VARVE
zelf meebrengt (`BOUWSTENEN` in `src/paneel/vrij.js`, data): dezelfde items als een vrij paneel, dus
dezelfde badges, kleuren en regels. Wat er niet is (geen superknoppen, geen stem) laat hij weg.
Wil je het anders, maak dan een eigen paneel (§3): een bouwsteen is een voorbeeld, geen keurslijf.

## 3. Zelf een paneel maken en op een scherm zetten (stap voor stap)

**Stap 1. Het paneel.** In je werkruimte (`werkruimtes/<naam>.json`, zie `docs/werkruimte/S3.md`)
onder `panelen`. Een paneel heeft een `titel` en `items`; elk item een `soort` en (behalve `tekst`)
een `action` van de bus. `{focus}`, `{tweede}`, `{speel}`, `{maatgever}` worden ingevuld zoals in de
mapping; met `"doel": "maatgever"` (of `speel`, `tweede`) betekent `{focus}` in dit paneel die track.

```json
"panelen": {
  "dub": { "titel": "DUB", "items": [
    { "soort": "draai",  "action": "track.{focus}.send.a" },
    { "soort": "draai",  "action": "track.{focus}.filter" },
    { "soort": "knop",   "action": "track.{focus}.play.quant", "label": "OP DE MAAT" },
    { "soort": "knop",   "action": "track.{focus}.kill.low.hold", "label": "BAS WEG" },
    { "soort": "schuif", "action": "track.{focus}.fader" },
    { "soort": "lamp",   "action": "track.{focus}.sync" },
    { "soort": "xy",     "action": "track.{focus}.fx.knob.{as}" },
    { "soort": "rij", "herhaal": ["pixel", "trails", "mirror"], "item": { "soort": "knop", "action": "video.fx.{k}.hold" } },
    { "soort": "tekst",  "tekst": "echo-worp: knop 1 vol, dan filter dicht" }
  ] }
}
```

Wat elk item doet:
- `draai`: een draaiknop (slepen omhoog = meer, shift = fijn); volgt de stand van de action.
- `knop`: indrukken = de action met `true`, loslaten = `false`, naar DEZELFDE action als het indrukken
  (ook als het deel of de focus intussen wisselde). Een `.hold`-action is zo een drukknop.
- `schuif`: een fader (plek in de baan).
- `lamp`: alleen een lampje (aan, gedimd, uit, zoals de LED's).
- `xy`: een vlak. X = `action`, Y = `y` (of `{as}` in de action: `1` links–rechts, `2` onder–boven).
  `druk`: een trigger zolang je vinger erop staat (een worp: `track.{focus}.fx.knob.2.hold`, `super.1.hold`).
  `los`: wat er bij loslaten gebeurt: `blijf` (standaard), `midden` (terugveren naar 0,5) of `terug` (naar
  de stand van vóór het aanraken). Eén vinger per pad; twee vingers = twee pads (elk zijn eigen
  pointerId). Waarden gaan hooguit één keer per beeld per as (de laatste wint); loslaten stuurt eerst de
  laatste stand. Het label = de namen van beide assen (de naam die het rack op een plek zet, anders de
  uitleg van de action); de stand komt van read(), dus ook een APC-draai beweegt de stip. Op een
  iPhone in portret neemt de pad de volle breedte. Voorbeeld (gemarkeerd als voorbeeld):
  ```json
  "xy": { "titel": "XY (voorbeeld)", "items": [
    { "soort": "xy", "action": "track.{focus}.fx.knob.1", "y": "track.{focus}.send.a",
      "druk": "track.{focus}.fx.knob.2.hold", "los": "terug" } ] }
  ```
  `y`, `druk` en `los` kent het model van S3 nog niet: hij laat ze staan in het bestand, en de mixer
  leest ze uit het ruwe bestand (`metRuw` in vrij.js; alleen als het model geen item weggooide).
- `rij`: hetzelfde item voor elke naam in `herhaal`, met `{k}` ingevuld.
- `tekst`: een tekst, verder niets.

Het label komt uit de uitleg van de action (zoals op de APC-kaart); een eigen `label` gaat voor. De
kleur volgt de soort van de action (dezelfde kleuren als `apc.html`). Een action die niet bestaat
wordt grijs, met één melding in de mixer. Op elk item staat welke control er in de open mapjes
naar wijst ("APC track knob 1", "Maschine draaiknop 3"), en het licht 300 ms op als je die control
aanraakt.

**Stap 2. Op een scherm zetten.** Per deel, per scherm:

```json
"delen": {
  "mix": { "label": "MIX", "kleur": "wit",
    "schermen": {
      "hoofd": { "werkvak": "paneel:dub" },
      "mac-2": { "vakken": ["uitlijn", "paneel:dub", "kaart"] },
      "ipad":  { "vakken": ["stand", "uitlijn", "paneel:dub"] } } },
  "uitlijn": { "label": "UITLIJN", "kleur": "groen",
    "schermen": {
      "hoofd": { "werkvak": "uitlijn-strook" },
      "mac-2": { "vakken": ["uitlijn:pagina:1"] },
      "ipad":  { "vakken": ["uitlijn", "secties"] } } }
},
"schermen": {
  "mac-2": { "soort": "venster", "plek": "onthouden" },
  "ipad":  { "soort": "ipad" }
}
```

De schermnaam (`mac-2`, `ipad`, of een eigen naam, ≤ 16 tekens: a-z, 0-9, -) is wat je in het adres
zet: `werk.html?s=mac-2`. Het scherm volgt het deel: wissel je in de mixer van deel, dan wisselen de
vakken mee.

**Stap 3a. Het tweede Mac-scherm.** Kies de werkruimte in de mixer en druk op **open schermen** op de
werk-balk: elk scherm met `"soort": "venster"` gaat open als venster van de mixer (zoals het
beamervenster). Sleep het naar het scherm waar je het wilt; het venster onthoudt waar het stond
(elke 2 s, in localStorage). De volgende keer zet "open schermen" het daar terug. Met de toestemming
"vensterbeheer" van Chrome (Window Management API) gebeurt dat op het label van het scherm, dus ook
als de schermen anders aangesloten zijn; zonder toestemming op de laatste positie. Staat een venster
op hetzelfde scherm als het beamervenster, dan zegt de mixer het. Dit venster MAG bedienen: elke klik
gaat over de bus van de mixer (dus in het handelingenlog), en het ene tabblad met de APC blijft het
ene tabblad.

**Stap 3b. De iPad** (Tailscale moet staan, `docs/TAILSCALE.md`):
1. Open in Safari `https://<NAAM>/werk.html?s=ipad`.
2. Deel-knop → **Zet op beginscherm**. Open hem voortaan vanaf het beginscherm: schermvullend, zonder
   adresbalk (`werk.webmanifest` en de apple-meta's).
3. Het scherm blijft aan zolang de pagina open is (Screen Wake Lock; opnieuw aangevraagd als je terugkomt).
4. **Tip voor een set: Begeleide toegang** (Instellingen → Toegankelijkheid → Begeleide toegang): driemaal
   op de zijknop houdt de iPad in deze pagina, zonder meldingen of per ongeluk wegvegen.

De iPad KIJKT in dit spoor: knoppen sturen niets (bedienen komt met S8, §6). Valt de verbinding weg
(wifi, de Mac slaapt, de server herstart), dan staat er een grote rode balk "geen verbinding met de
mixer"; zodra de server terug is, komt binnen een paar seconden alles terug. Een halve cirkel (◐)
rechtsboven = de server is er, maar de mixer zendt niets: kies een werkruimte in de mixer (niet
`standaard`) en houd het tabblad met de APC open.

**Noodweg**: valt het paneel uit, dan is de hub-cockpit er nog (de nagemaakte APC van de AV-app-hub op
de iPad, alleen met de hub).

**Stap 4. Nakijken.** `curl -s http://localhost:8777/api/werkruimtes/<naam> | python3 -m json.tool` geeft
fouten en waarschuwingen (een paneel met een action die niet bestaat: "grijs"). In de mixer:
`window.varveSchermen.nodig()` = de actions die de panelen lezen; `window.varveSchermen.zender.stats`.

## 4. Hoe het werkt (voor wie eraan komt)

**Opener (mac-2).** `werk.html` leest `window.opener.varvePaneel` elk beeld: `read`, `invoke`, `metaOf`,
`label` (beschrijf), `vars` (+ `varsSleutel`), `badges` (+ `badgeSleutel`), `geraakt` + `nu` (de klok van
de MIXER: een popup heeft een ander nulpunt van performance.now), `werk()` + `werkSleutel()`, `kaart()`,
`invoer()` (de uitlijn, van S2), `decks()`. Geen berichten, geen kopie: zo is een APC-draai in het
eerstvolgende beeld zichtbaar. Alles wat per beeld gevraagd wordt is een sleutel die alleen verandert
als er iets veranderde (op mac-2 draait dit in de thread van de mixer).

**Server (de iPad).** De mixer (`live-zender.js`, alleen met een werkruimte, alleen het tabblad dat
`statusVanMij` zou zijn: de lockhouder, met `?hub=` het verbonden tabblad):
- zonder kijker: 1×/s `GET /api/paneel/kijkers`, verder niets;
- met een kijker: 8 pings (klokverschil met de server), dan een volledige `stand`, daarna per 20 ms
  hooguit één POST met wat veranderde: reads ≤ 10/s per id, een `tijdlijn` bij een nieuwe segId (of
  gridVersie, wacht, rem), `deck` als titel/grid/bpm/secties veranderen, `maatgever`, `werkruimte`
  (panelen, labels, badges, kaart, vars; ≤ 4×/s gekeken), en `klok` 1×/s (meteen, hooguit 10×/s, als de
  audioklok > 1 ms versprong);
- de server wijst de mixer na een fout terug naar vragen (en opnieuw pingen: een herstarte server is
  een nieuw proces met een eigen klok).

De server (`PaneelRelais`) houdt de volledige stand bij; een nieuwe kijker krijgt hem meteen, daarna
alleen verschillen, en 1×/s een `hb`. Zonder kijker is de stand "niet vers": de volgende kijker
wacht op een nieuwe stand van de mixer (≤ 1 s). Een ander tabblad telt niet tot het eerste 3 s stil
is EN het nieuwe met een stand begint.

**Regel 3 over het netwerk.** De iPad rekent zelf: `positieIn(tijdlijn, ctx)` met `ctx` = de audioklok
van de mixer op de serverklok (`ctxOp`), en dan `hoorbaar()` van `hoorbaar.js` met de V van de mixer.
`currentTime` springt in Chrome per blok van de audiothread (headless 512 frames, 10,7 ms) en staat
daartussen stil; de klok die de mixer stuurt volgt het MIDDEN daarvan (getOutputTimestamp, glad, plus
het gemiddelde verschil met currentTime over de laatste 32 metingen; `besteMeting` in protocol.js).

**Het werkvak** (`#werkvak`, boven de rijen): bij het event `'werkruimte'` van S3 (en bij het opstarten,
als de werkruimte al gekozen was) het vak van `schermen.hoofd.werkvak`. Een `paneel:<id>` gebruikt
de gewone controls van de mixer: `.knob`, `input[type=range]` en `[data-kind=button]` met hun
`data-action`, `vensters.bind(root)` meldt ze aan bij de renderloop, `ontbind(root)` haalt ze weg
(een knop die nog ingedrukt is laat los naar zijn action). Hoogte hooguit 34vh, scrolt zelf.

**Regels die blijven gelden** (de lag-winst van 14 okt): geen `:has()`; niets in het MIDI-bericht
(`bijInvoke` schrijft alleen een tijd op, het paneel kijkt in zijn volgende beeld); geen opmaak lezen in
een lus (`getBoundingClientRect` alleen bij het indrukken van een schuif of xy); schrijven alleen wat
verandert (`zet`, sleutels).

## 6. Wat S8 moet aansluiten (bedienen vanaf de iPad en de iPhone)

Klaar in dit spoor:
- de berichtvorm: `invokeBericht({ id, v, druk, seq, scherm })` en `isInvoke(b)` in `src/paneel/protocol.js`
  (`druk` 'aan'/'los' bij knoppen, null bij waarden; `seq` per scherm oplopend);
- `ServerVerbinding.zetSchrijver(fn)` (verbinding.js): met een schrijver krijgt de verbinding een `invoke`
  en wordt `kanBedienen` true; vrij.js bedient dan vanzelf (per pointerId, loslaten naar dezelfde action,
  waarden per beeld gebundeld, xy met druk en los). Zonder schrijver: kijken (zoals nu);
- de pagina-id per verbinding (`?k=`), waarmee de server weet welk scherm het is.
S8 bouwt:
1. de route (bv. `POST /api/paneel/invoke` of een tweede SSE-kanaal naar de mixer, C4), standaard 404 tot de
   schakelaar in de Controlekamer aan staat; Host/Origin; koppelcode → token-cookie;
2. in de mixer het uitvoeren: alleen wat in de panelen/bouwstenen van DAT scherm in het actieve deel staat
   (`nodig()` in `src/ui/aanhakers/schermen.js` rekent die lijst al uit) én `magOpScherm` (model.js, met de
   vaste lijst VAST_NOOIT: laden, library, opnemen, log, mapping, werkruimtes nooit);
3. bij wegvallen (geen SSE/ping binnen 1,5 s) alles loslaten wat met `druk: 'aan'` binnenkwam;
4. rem (120/s per scherm), `seq` tegen dubbel, het antwoord `{ t: 'antwoord', seq, ok, reden }`, en in het log
   `bron: 'ipad'`;
5. in werk.html `verb.zetSchrijver(...)` aanroepen als het scherm gekoppeld is (één regel in paneel.js).

## 7. Niet getest, aannames

- **Alleen op de echte iPad te bevestigen**: Safari (EventSource, `navigator.wakeLock` sinds iOS 16.4),
  het beginscherm (`display: standalone`, de apple-meta's), dat het scherm wakker blijft, Begeleide
  toegang, touch met echte vingers (touch-action, meerdere vingers), wifi die even wegvalt, de iPad die
  op slot gaat en terugkomt (visibilitychange). Headless is de iPad een tweede browsercontext in
  dezelfde Chrome op 127.0.0.1.
- **Alleen op de Mac te bevestigen**: de Window Management API met twee echte schermen (toestemming,
  labels, `window.open` met left/top op het andere scherm), de waarschuwing naast het beamervenster
  (vergelijkt `screen.availLeft/availTop/width` van beide vensters), Tailscale (Host/Origin zijn met
  `VARVE_HOSTS` getest, niet met een echte `tailscale serve`).
- **De klok in deze container: de eis "binnen 5 ms" wordt alleen op een rustige machine gehaald.** De audioklok van headless
  Chrome loopt op een nep-audioapparaat dat onder CPU-druk hapert, en `currentTime` springt per 10,7 ms
  (dus `hoorbaar()` in de mixer zelf ook). Gemeten met `werk-ipad.mjs --duur 60` (seek, loop en rem):
  mediaan 1,1–1,6 ms; gemiddeld over een reeks van 100 ms p99 3,8–4,3 ms en max 4,5–5,8 ms bij een
  rustige machine (de laatste run gehaald), tot ~28 ms onder load 5–10; de 300 ms na een sprong tellen niet mee (het nieuwe segment is
  dan onderweg: daar max ~6 ms). Op de Mac met een echt audioapparaat verwacht ik minder; meten (proef D).
- Aanname: een herladen mixer-tabblad (nieuw tab-id) wordt door de server pas na 3 s stilte van het
  oude geaccepteerd; de iPad wacht dan hooguit ~4 s op de nieuwe stand.
- Aanname: `xy` met `{as}` (1 en 2). Het model van S3 kent maar één `action` per item.
- De iPad haalt geen peaks, tellen of klappen: de uitlijnweergave op de iPad toont gridlijnen en
  getallen (grid Δ, drift, maat), muziek Δ is daar "–".
