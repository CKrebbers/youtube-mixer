## De rekenregel

**De as** staat in tellen van de maatgever M zoals je hem HOORT:
`b_nu = beatAt(positieIn(tijdlijn_M, nu − V))`, met V = `uitgangsVertraging(ctx)` (hoorbaar.js).
Lc = de hoorbare tellengte van M op de klok (tel / R). Een pagina is 1 of 2 maten en begint op
een "1"; hij slaat om als de speelkop eraf loopt. Alleen de speelkop beweegt (CSS-transform).

**Een baan.** De klok op tel b van de as is `c(b) = nu + (b − b_nu) × Lc`; wat je dan van track i
hoort is `pos = positieIn(tijdlijn_i, c(b) − V)`. Dat is "positie − V × rate", maar precies:
- in een loop vouwt hij terug (geen sprong als de loop rondgaat: de baan wordt op de naad
  geknipt in stukken);
- een track die op de maat WACHT (`play.quant`) begint met een stuk zonder tracktijd en valt in
  op de "1" waar hij invalt;
- een rem wordt in 24 stukjes getekend (geen rechte lijn);
- een geplande sprong met keylock speelt `vorig` tot hij ingaat;
- een track in PAUZE wordt getekend alsof hij nu zou starten, vastgemaakt aan de speelkop.

Gridlijnen staan op de eigen tellen van de track (de "1" voller), de gevonden tellen
(`deck.tellen`) als korte streepjes onderaan, de klappen (`deck.onsets`) bovenaan.

**De getallen** (+ = de track loopt VOOR op de maatgever):

| getal | regel |
|---|---|
| grid Δ | fase van het grid van i min die van M op wat je hoort, gevouwen in ±½ tel, × tellengte. Gelijk aan `engine.faseVerschil` (headless: 0,000 ms verschil op zeven tracks) |
| muziek Δ | `faseTussen`: de mediaan van de laatste 8 gehoorde tellen van i tegen de dichtstbijzijnde gehoorde tel van M (minstens 4 paren). Met alleen klappen: "grof ±15 ms" |
| drift | `16 × (L_M − L_i)` in ms: zoveel loopt hij uit per 16 tellen |
| maat | tellen naast de "1" van M (−2 … +2), los van de fase |
| ⚠ | `afwijkingBij` (tellen.js) zegt dat het grid van deze track naast zijn eigen tellen ligt: vastzetten, niet duwen |

Kleur: groen < 3 ms, geel < 10 ms, rood daarboven.

**De vouw**: per track de laatste 32 gehoorde tellen (tellen, anders klappen, anders grid) als
stip op hun fase t.o.v. de dichtstbijzijnde tel van de as; die van M als ijkpunt. Gelijk = één
stapel, drift = schuin, flam = twee stapels.

**De sleutel**: `deck:segId:gridVersie:inhoud | M:segId:gridVersie:loopt | pagina:maten |
breedte | zoom | soort | V`. Een tekst van een paar getallen; geen `JSON.stringify(grid)`.
Zonder verandering wordt er niets getekend: per baan een strook in tracktijd (tegels van 1024 px,
hooguit 24 per track), die per keer met één `drawImage` op de pagina komt.

**De invoer** is één object `{ decks, maatgever, V, nu }` (`invoerVanEngine(engine)` maakt hem in
de mixer). De iPad (S7) geeft dezelfde vorm uit segmenten van buiten en zijn eigen klok.

## Kosten (gemeten)

```
node test/uitlijn.test.mjs
VARVE_TMP=<tmp> VARVE_CHROME=<headless_shell> node tools/headless/uitlijn.mjs <uitmap>
```

Headless in deze container (software-GPU, swiftshader; acht tracks, alles speelt, in rust):

| wat | gemeten | grens |
|---|---|---|
| pagina in uitlijn.html | 0,16 Mpx/s (2,2 tekenbeurten/s) | ≤ 3 Mpx/s |
| vouw in uitlijn.html | 1,06 Mpx/s | ≤ 3 |
| rekenwerk | 0,267 ms per beeld gemiddeld (max 5,5 ms: het eerste beeld na een omslag) | ≤ 0,5 ms |
| hoofdvenster met uitlijn.html open | 0,29 beelden/s minder (mediaan van 4 paren stil/lopend) | < 1 |
| strook in de mixer (toonInWerkvak) | 0,18 Mpx/s erbij | ≤ 3 |
| getallen in het DOM tegen `engine.faseVerschil` | 0,000 ms op 7 tracks | ≤ 0,5 ms |
| uitlijn.html: AudioContext, MIDI, Web Lock | 0, 0, 0 | 0 |

Muziek Δ wordt twee keer per tel gerekend, niet elk beeld. De beeldsnelheid van het hoofdvenster
zelf (8–16 b/s) zegt hier niets: de container deelt zijn CPU met de andere sporen.

## Niet gemeten

- **GPU op de M1** (Metal): `drawImage` van tegels en de CSS-transform van de speelkop kosten op
  echte hardware anders dan op swiftshader. Proefpunt avond A: uitlijn.html op het tweede scherm
  naast de mixer met acht tracks, en `tools/headless/uitlijn.mjs` op de Mac zelf.
- Op echte muziek: of "muziek Δ" klopt met het oor (avond A). Hier zijn de tellen synthetisch.
- Slepen met `track.N.phase.offset`: die action komt van S1. Zonder S1 doet slepen niets (getest);
  met S1 is het pad getest op een nep-bus (de juiste fractie), niet in echte Chrome.

## Zelf invullen (Clay)

De weergave is een bouwsteen; WAAR hij staat en in welke vorm kies je zelf, in data:

1. **Los venster**: de knop **uitlijn** achteraan de transportrij van de focus-track. De vorm
   (pagina · vouw · strook) en 1 of 2 maten kies je bovenin; het venster onthoudt het. Een
   bladwijzer of een werkruimte kan het meegeven: `uitlijn.html?vorm=vouw&maten=1`.
2. **In een werkruimte** (S3, `docs/WERKRUIMTE.md` B2) schrijf je een vaknaam bij een deel en een
   scherm. Voorbeeld:
   ```json
   "uitlijn": {
     "schermen": {
       "hoofd": { "werkvak": "uitlijn-strook" },
       "mac-2": { "vakken": ["uitlijn:pagina:1"] }
     }
   }
   ```
   Namen: `uitlijn` (pagina, 2 maten), `uitlijn-pagina`, `uitlijn-strook`, `uitlijn-vouw`, of
   `uitlijn:<pagina|strook|vouw>[:1|2]`. Een onbekende naam doet niets.
3. **Een knop om te duwen** kies je in je eigen mapping (S1 levert `track.N.phase.offset`); slepen
   in een baan gebruikt dezelfde action, dus wat je daar koppelt is wat slepen doet.

Voor wie bouwt: `varveUitlijn.toonVak(el, naam)` geeft `{ weergave, zetVorm, stop }` (of null
als het geen uitlijnvak is) en tekent op `ctx.renderloop` zolang hij staat; `stop()` haalt hem weg.
