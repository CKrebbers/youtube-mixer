# Werkruimte S3: de kern (14 okt 2026)

Het ontwerp staat in `docs/WERKRUIMTE.md` (A1–A12, B1–B6, C2, D4 "S3"). Dit document zegt wat er
GEBOUWD is, hoe het in elkaar zit, en vooral: **hoe je zelf een werkruimte maakt**. Afspraak met
Clay (14 okt): Clay maakt zelf de indeling (welke knop wat doet, welke schermen, welke effecten).
S3 levert het mechaniek als data, plus kleine voorbeelden.

Zonder werkruimte (`standaard`) doet VARVE precies wat hij deed: de mapping is regel voor regel
die van vandaag (met je eigen verschil), de werk-balk is `hidden`, ⇧ master-knop is beeld zwart.

## 1. Wat er is

| bestand | wat |
|---|---|
| `src/werk/model.js` | het formaat (schema 1), puur: `normaliseerWerkruimte`, `normaliseerStuk`, `samenstellen`, `bereikbaarheid`, `kleurControle`, `telNieuwePlekken`, `mapjesVanDeel`, de kern (`KERN`, `isKern`, `BESCHERMD`) |
| `src/werk/werkruimte.js` | de werkruimte in de mixer: deel, wie koos (`door`), onthoud, volgt, THUIS, vereist/terugval, vastleggen, peilen (`maakHaler`, ETag) |
| `src/werk/apparaten.js` | `registreerApparaat(id, { zetMapjes(def), mapjes(), aanwezig() })`; `maakApcAdapter` (drukt op kiesknoppen = `layer.*` over de bus) |
| `src/werk/kleuren.js` | deel → paletnaam (MIX wit, UITLIJN groen, FX violet, STEMS zeegroen, SECTIES hemelsblauw, SPELEN oranje, BEELD geel, LIBRARY grijs) |
| `src/control/acties-werk.js` | `werk.deel.<naam>`, `werk.deel.1–8`, `werk.deel.next/prev`, `werk.thuis`, `werk.vastleggen`, `werk.kies` (alleenScherm); allemaal `log: 'overslaan'` |
| `src/ui/werk-balk.js` | `#werk-balk`: tabs in hun kleur, wie het koos, "⚠ N nieuw", THUIS, de kiezer (voorbeelden met "(voorbeeld)"), "leg vast in <deel>", `voegKnopToe(el)` voor andere sporen |

| `server/werkruimtes.js`, `server/routes/werkruimtes.js` | `GET /api/werkruimtes`, `GET/PUT /api/werkruimtes/<naam>` (versie, 409 met de huidige inhoud), `GET …/<naam>/versies` |
| `src/standen/stand-model.js`, `server/standen.js` | een stand mag `werkruimte: { naam }` hebben: activeren = die werkruimte bij de (volgende) start van de mixer |

Eigen werkruimtes staan in `werkruimtes/<naam>.json` in de projectmap (niet in git, `.gitignore`).
Een eigen bestand gaat vóór een voorbeeld met dezelfde naam; wie een voorbeeld aanpast en opslaat,
krijgt een eigen bestand (het voorbeeld in git blijft staan). Testservers: `VARVE_WERKRUIMTES`.

## 2. Zelf een werkruimte maken (stap voor stap)

**Stap 1. Een bestand.** Maak `werkruimtes/mijn.json` (naam = bestandsnaam: kleine letters, cijfers,
`-`, `_`). Het kleinste dat werkt:

```json
{
  "schema": 1,
  "naam": "mijn",
  "titel": "Mijn avond",
  "stukken": ["basis"],
  "deel": { "start": "mix", "kiezen": "volgt", "onthoud": true },
  "delen": {
    "mix":   { "label": "MIX",   "kleur": "wit",      "apc40mk2": { "grid": "hotcues", "device": "strip" }, "schermen": { "hoofd": { "rijen": [] } } },
    "stems": { "label": "STEMS", "kleur": "zeegroen", "apc40mk2": { "grid": "stems" },                        "schermen": { "hoofd": { "rijen": ["stems"] } } },
    "fx":    { "label": "FX",    "kleur": "violet",   "apc40mk2": { "device": "rack" },                       "schermen": { "hoofd": { "rijen": ["master"] } } }
  },
  "volgt": [
    { "apparaat": "apc40mk2", "mapje": "grid.hotcues", "deel": "mix" },
    { "apparaat": "apc40mk2", "mapje": "grid.stems",   "deel": "stems" }
  ]
}
```

Wat elk veld doet:
- `stukken`: knoppen die erbij komen, uit `mappings/stukken/<naam>.json` (zie stap 4). `basis` = THUIS op ⇧ master-knop.
- `deel.start`: het deel waarmee je begint en waar THUIS naar teruggaat.
- `deel.kiezen`: `volgt` = het deel volgt wat je op de APC vast openzet (zie `volgt`); `expliciet` = alleen
  tabs, F1–F8, `werk.deel.*`.
- `deel.onthoud`: kom je terug in een deel, dan staan de mapjes zoals je ze daar achterliet (alleen deze sessie).
- `delen`: hooguit 8, in deze volgorde = tab 1–8 (`werk.deel.1–8`). Per deel een `label` (≤ 8 tekens), een
  `kleur` (een naam uit het APC-palet: wit, groen, violet, zeegroen, hemelsblauw, oranje, geel, grijs, rood …),
  per apparaat welke mapjes open gaan (APC: `grid` = hotcues/loops/sampler/video/klank/stems/patronen/auto/secties,
  `device` = strip/rack/inst/master/beeld; wat je niet noemt blijft zoals het staat), en per scherm wat er open gaat
  (`hoofd.rijen` = auto, beeld, instrument, klankschaal, koptelefoon, master, stems, patronen;
  `hoofd.onderpaneel` = library; `hoofd.werkvak` = wat andere sporen in het werkvak tonen).
- Een mapje mag afhangen van de stand: `{ "als": "focus.instrument", "dan": "inst", "anders": "strip" }`
  (condities: focus.instrument, focus.nummer, focus.stems, focus.leeg, speel.instrument, hub, apparaat.<id>).
- `volgt`: welk VAST geopend mapje (kort drukken; gluren ≥ 400 ms telt niet) welk deel kiest.

**Stap 2. Kiezen.** Open de mixer met `http://localhost:8777/?werk=mijn` (wordt onthouden), of kies hem in de
kiezer op de werk-balk. `?werk=standaard` of "standaard" in de kiezer = terug naar VARVE zoals altijd.

**Stap 3. Inrichten door te doen.** Zet in een deel de mapjes en rijen zoals je ze wilt, en druk twee keer op
"leg vast in <deel>" (binnen 3 s). Dat schrijft het bestand (met versie; de vorige gaat naar
`werkruimtes/.versies/mijn/`). Zo hoef je de JSON voor mapjes en rijen niet te typen. Een conditie
(`{ "als": "focus.instrument", "dan": "inst", "anders": "strip" }`) blijft staan zolang ze nu precies het
open mapje geeft; opende je zelf iets anders, dan wordt dat het deel.

**Stap 4. Eigen knoppen.** Twee plekken:
- in de werkruimte zelf, `regels` (alleen voor deze werkruimte):
  ```json
  "mapjes": { "nieuw": { "device.mijndub": { "naam": "mijn dub", "kiesknop": { "in": "note:0:58", "shift": true } } } },
  "regels": { "apc40mk2": [ { "in": "note:0:58", "laag": "device.mijndub", "action": "track.{focus}.send.a", "mode": "druk", "naar": 1 } ] }
  ```
  (⇧ Device ◀ opent het nieuwe mapje "mijn dub"; daarin geeft Device ◀ de echo een duw zolang je drukt.)
- of als STUK in `mappings/stukken/<naam>.json` (herbruikbaar in meerdere werkruimtes), zoals `basis.json`:
  `{ "schema": 1, "stuk": "<naam>", "titel": "…", "mapjes": { "nieuw": {…} }, "regels": { "apc40mk2": [ … ] } }`.

Een regel heeft dezelfde vorm als in `mappings/apc40mk2.json` (`in`, `shift`, `laag`, `action`, `mode`), plus
de modi `druk` (zolang je drukt naar `naar`, loslaten = terug), `latch` en `stappen`. Wil je weten welke
plekken vrij zijn: `apc.html` toont wat elke knop nu doet; de werkruimte weigert een bezette plek met een reden.

**Stap 5. Nakijken.** Bij elke opslag (en bij het peilen) zegt de server wat er mis is. Of met de hand:
```sh
curl -s http://localhost:8777/api/werkruimtes/mijn | python3 -m json.tool | grep -A20 '"fouten"\|"waarschuwingen"'
```
Een FOUT = niet opgeslagen (400 met de reden). Een WAARSCHUWING = overgeslagen, de rest werkt (een stuk dat er
nog niet is, een mapje dat het apparaat niet kent, een kleur die niet bij de grid-modus past, > 12 nieuwe plekken).

**Claude laten schrijven.** Claude mag `werkruimtes/<naam>.json` direct schrijven; de mixer peilt elke 2,5 s en zet
de nieuwe versie op zonder het deel te wisselen (een mapje dat je in dat deel met de hand opende blijft open,
tenzij het bestand juist dat deel voor de APC veranderde). Via de API: `PUT /api/werkruimtes/<naam>` met
`{ werkruimte, versie }` (de versie uit de GET); een oude versie geeft 409 met wat er nu staat.

## 3. Wat een werkruimte NOOIT kan (het model weigert)

- iets weghalen of verbergen (`uit`, `verberg`, `acties` …), klanken of standen zetten (`start`, `waarden` …);
- een regel op de KERN (faders, play, cue, sync, A|B, crossfader, ● = PFL, de master-knop zonder shift …):
  die doen in elke werkruimte hetzelfde. Vrij binnen de kern: ⇧ A|B, ⇧ Lock, ⇧ master-knop;
- een houd-, druk- of latch-regel op play, cue, op de maat, hotcues, laden of mapjes (`layer.*`);
- een mapje onbereikbaar maken (elk mapje een kiesknop, of in een deel); meer dan 8 delen;
- `werk.kies` op een knop (een andere werkruimte kies je alleen op het scherm);
- op een ander scherm (de iPad): opnemen, log, mapping, werkruimtes, library, laden (`VAST_NOOIT`).

## 4. Gedrag in de mixer

- Een deelwissel zet ALLEEN mapjes (via `layer.*` op de bus), rijen, het onderpaneel en het werkvak (event
  `'werkruimte'` met `{ naam, deel, def }`). Nooit een klank: 0 invokes buiten `layer.*`/`werk.*` (bus-spion).
- Het event `'werkruimte'` (voor S2/S7) komt in het VOLGENDE BEELD (`plan`, samen met rijen en onderpaneel),
  nooit in het MIDI-bericht van de wissel; twee wissels in één beeld = één event voor de laatste. Een
  luisteraar mag dus werk doen, maar geen eigen `requestAnimationFrame`-lus erop bouwen die per event iets leest.
- `volgt` maakt geen lus: een wissel die van de APC komt, zet de APC niet opnieuw.
- Nog eens op het deel drukken dat al actief is, doet NIETS (zoals een radioknop): wat je binnen het deel
  met de hand opende blijft open. Terug naar de indeling van het deel = THUIS of een ander deel en terug
  (met `onthoud` komt dan wat je had; THUIS wist dat).
- HERLADEN (Claude schreef het bestand, de peil na een 409 bij vastleggen, een terugval) verandert je indeling
  niet: het deel blijft als het er nog is, en per apparaat gaat weer open wat er vóór stond, ook een mapje uit
  een stuk of uit de werkruimte zelf (grid.fx, device.uitlijn, mijn dub). Het weghalen en terugzetten gaat
  STIL (`adapter.stil`): volgt hoort het niet. Alleen als het deel voor dat apparaat veranderde, of het mapje
  er niet meer is, geldt het deel. `onthoud` blijft voor de delen die niet veranderden.
- Een TERUGVAL (de Maschine valt weg) houdt het deel en het APC-mapje als de terugval dat deel ook heeft.
- Peilen: nooit twee verzoeken tegelijk, een tijdgrens van 5 s per verzoek (`HAAL_MS`), en een antwoord dat
  pas na een andere keuze binnenkomt telt niet. Op de server delen werkruimtes en standen één grens van
  2 fs-operaties (`beperkt` in server/standen.js): een werkruimte die iCloud niet teruggeeft = 503 na 2 s,
  en daarna start er geen nieuwe draad.
- THUIS (`werk.thuis`, ⇧ master-knop met het stuk basis, de knop op de balk): deel = start, de standaardmapjes
  op elk apparaat, gluren en vasthouden los, het onthouden weg. Klank en faders blijven staan.
- `vereist` + `terugval`: ontbreekt een vereist apparaat (bij het kiezen of omdat het wegvalt), dan de terugval,
  met één melding. Komt het terug: niet vanzelf terug, wel één melding met een knop (en de knop op de balk).
- "⚠ N nieuw" op de balk: het aantal plekken dat deze werkruimte anders maakt dan wat je het laatst zag
  (A11); weg na een keer kijken.
- W1 (open vraag, tot dan zo): opslaan (`PUT`) mag alleen vanaf deze Mac (`vanDezeMac`); via Tailscale/de iPad
  alleen lezen (403 met reden).
